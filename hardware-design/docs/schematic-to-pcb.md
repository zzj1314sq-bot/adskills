# 原理图增量修改与限定转 PCB

目标：把确认后的链路变化落到原工程、原页面和原 PCB，保护范围外设计。库缺失时先走[封装设计](footprint-design.md)，平台要求见[统一 AD26](platform-policy.md)。

## 1. 接收明确的变更清单

第一部分的 Visio/链路设计至少输出：器件型号、级联顺序、接口方向、引脚网络、供电控制、封装要求、增删替换清单，以及必要的损耗和功率依据。

第二部分开工前一次查齐：

- 目标工程、源页面、PCB 和实际库来源；各自的保存状态与文件指纹。
- 当前宿主、实际 AD 版本、MCP 身份及所需能力，而非沿用旧 PID 或旧响应。
- 选定器件的源 UID、现有模型、PCB 对应身份；重复/歧义身份必须处理。
- 新增、删除、换封装、改名、网络变化，以及全部范围外器件的保留清单。
- 缺封装的明确暂缓项、原图与 PCB 既有差异、真实板框和临时板外位置。

保留未保存的用户编辑，不通过 SaveAll、整项目 ECO 或覆盖缓存来绕过限定范围。

## 2. 在原图上增量修改

保留原文档身份、原页面、未涉器件的 UID、位置、文字和图元；明确修改信号、电源、控制、去耦与隔直。不要把“图上有同名标签”直接当作已经实际连通。

替换器件核真实引脚功能与供电，已有配套电容、偏置和接口是否仍适用；删除器件还需清理其旧导线和旧网络影响。

原理图保存后同时核对实际引脚连接和唯一真实模型。原图增量任务不交付另画的一整页候选来替代原页面。

## 3. 从新鲜快照制作限定计划

使用本次源、工程、PCB、库指纹和原生编译引脚网络，生成限定差异计划。

UID 优先，层级 SourceUniqueId 保留完整标识；同名不能抢占另一个有效 UID。所有未匹配 PCB 器件都必须分类为保留、删除或待决，不能只因源器件全部匹配就宣称完成。

额外地焊盘映射绑定准确 UID、模型与接地依据，不把所有 pad0 自动接地。历史新增能力每批上限和单来源库约束按当前实现核实，不能从一次任务自行扩展上限。

## 4. 必要副本测试与正本写入

对新增、新范围和未覆盖替换，先在受控副本执行该批真实计划，独立审计、保存重开、重新规划，确认无待同步差异并关闭测试标签；准确依赖和输入不变后才应用正本。

已有准确验收且输入未变的部分可以复用；源、库、工程、测试范围或正本变化则重算相应部分。必要分批门禁仍保留，不把历史测试借给新范围。

超时后先查原请求终结、内存和磁盘状态，保留写锁与检查点，不重发结果未知的写入。

## 5. 一次完成收尾

- 新增件按真实封装、文字包围框和间距暂放在真实板框外；不能只离开原器件区域，或用固定中心网格假定没有重叠。
- 本项目新增 PCB 位号使用 Arial、TrueType、1.5 mm、居中；范围外既有文字保持。
- 更新连接缓存，核对飞线确随新焊盘位置刷新，同时证明实际网络没有被清空。
- 正常保存、关闭重开正本；重新编译与预检源/PCB 差异，关闭本次测试文档，返回正本。
- 回写 Visio 实施标注、实际状态、证据、限制和接续点。

已知模态确认可能阻塞 `application.run_process`。显示 busy 或请求超时不等于崩溃；应确认具体窗口与原请求结果。脚本/过滤器与 MCP 的引擎占用按当前基线管理，不能重复派发来掩盖阻塞。

## 6. 独立审计保留哪些检查

| 对象 | 核对方式 |
|---|---|
| 组件 | 新增/替换/删除准确集合；未涉位置、旋转、图层及参数保持 |
| 焊盘 | 真实引脚网络、编号多重集、尺寸、位置、旋转及相关工艺字段 |
| 文字 | 内容、字体、尺寸、位置、旋转、线宽；模型内部文字与新模型比较 |
| 走线/过孔/区域等 | 根据真实所属器件与网络身份比较，保护非目标几何 |
| 覆铜 | 比较真实网络及完整设置/几何；序列化 NET 索引改变本身不等于换网 |
| 保存规范化 | 出现未知差异时，用相同输入指纹的独立只保存对照精确证明，不全局忽略流 |
| 派生缓存 | 只接受有证据的具体清理字段，实际网络名、连接及设计属性保持 |

完成同步不等于完成布线、全工程 ERC/DRC、射频性能或制造验收。[本次实际结果与边界](../cases/2026-11-25-rf-incremental-update.md)
